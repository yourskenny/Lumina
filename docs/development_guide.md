# 开发指南 (Development Guide)

本文档旨在介绍本项目的核心技术架构及各模块的集成开发细节。

## 1. 架构概述：端云协同架构 (Hybrid Cloud-Local Architecture)
本项目采用端云协同的混合架构，结合了本地高效的实时处理能力和云端强大的认知推理能力。

- **本地端 (Local)**: 负责高频、低延迟的任务，如视频流的接入、YOLO 实时目标检测、基础状态监控及语音唤醒等。
- **云端 (Cloud)**: 负责高算力需求的复杂任务，如基于 Qwen VLM 的视觉语言理解、复杂逻辑推理和对话生成。

这种架构设计的优势在于：**本地处理保障了系统的实时性和基础安全性，而云端大模型则赋予了系统高级的认知与交互能力，同时有效平衡了算力成本与网络带宽消耗。**

## 2. 核心模块说明

### 2.1 本地 YOLO 目标检测 (YOLO Local)
- **实时性保障**: 使用轻量级 YOLO 模型在本地进行视频帧的逐帧或抽帧检测，确保对环境变化的快速响应。
- **数据过滤与事件触发**: 本地检测结果可作为云端大模型的先验信息，过滤掉无意义的背景帧。仅在关键事件发生（如检测到行人靠近、红绿灯状态改变等）时，才会触发云端 VLM 请求，从而显著节省带宽和云端算力。

### 2.2 云端 Qwen VLM (Qwen VLM Cloud)
- **多模态理解**: 接收本地上传的关键帧图像和用户语音文本，利用通义千问视觉语言模型 (Qwen VLM) 进行深度的场景理解和逻辑推理。
- **上下文记忆**: 结合历史对话上下文，提供连贯、准确的智能问答和决策建议。

## 3. 语音交互集成 (TTS/STT Integration)
本项目通过集成先进的 STT (Speech-to-Text) 和 TTS (Text-to-Speech) 服务，实现全语音的自然人机交互闭环。

- **STT (语音转文本) 集成**: 
  - 负责将用户的语音指令实时转换为文本，作为输入传递给 Qwen VLM 或本地控制模块。
  - **开发要点**: 需在本地处理环境噪音，并结合 VAD (Voice Activity Detection) 算法实现精准的端点检测，避免无效音频传输。
- **TTS (文本转语音) 集成**: 
  - 将云端 VLM 返回的文本结果合成为自然流畅的语音并播放给用户。
  - **开发要点**: 采用流式 TTS (Streaming TTS) 技术以降低首字响应延迟 (TTFB)，确保交互的自然度。

## 4. 提示词工程策略 (Prompt Engineering Strategy)
为了使 Qwen VLM 能够稳定输出符合预期的结果，并适配 TTS 的语音播报特性，我们制定了以下提示词策略：

- **角色设定 (System Prompt)**: 明确 AI 的身份、职责和语气。例如：“你是一个专业的视障人士出行辅助助手，请用简明扼要的语言描述前方的障碍物。”
- **结构化知识注入**: 将本地 YOLO 检测到的标签（如 `['car', 'person']`）以及其相对位置信息，与图像一起作为 Context 传入，增强大模型的先验知识，降低幻觉率。
- **输出格式限制**: 强制要求模型输出特定的 JSON 格式或限制回复长度。例如增加指令：“请用不超过 20 个字回答，必须口语化，不要包含 Markdown 符号”，以确保 TTS 播报的简洁性和有效性。
